# Inbound workflow webhooks

Lets an external system — a payment gateway, an ERP, anything that can make
an HTTP request — advance a record's workflow directly, without a logged-in
Backpack user. This document is for whoever is integrating an outside system
against a workflow built with this engine.

## 1. Mark an edge as webhook-triggered

In the designer, open the edge you want an external system to be able to
fire and set **Trigger** to `webhook`. Only edges declared this way can ever
be fired through this endpoint — a signed URL for a webhook edge can't be
used to fire a `manual` or role-gated edge instead, and a `manual` edge can
never be fired this way even with a valid signature.

## 2. Get the signed URL

The URL is generated by the app, not by the integrator. Call this from your
own code, wherever it makes sense to hand the URL to the external system
(e.g. when creating the outbound request that kicks off their process):

```php
$url = $purchaseRequest->signedWebhookUrl('vendor_confirmed');
```

This returns a URL that never expires by default — safe to store on the
external system's side and call whenever their event actually happens. Pass
an expiration as the second argument for a one-off, time-boxed link instead:

```php
$url = $purchaseRequest->signedWebhookUrl('vendor_confirmed', now()->addDays(7));
```

`signedWebhookUrl()` returns `null` if the record has no active workflow
instance to target.

The URL itself looks like:

```
https://your-app.test/workflows/webhook/{instance_id}/{edge_id}?signature=...&expires=...
```

You never construct or sign this yourself — treat it as an opaque link the
app gives you.

## 3. Call it

```
POST {the signed URL}
Content-Type: application/json

{
    "inputs": {
        "reference": "PAY-12345"
    }
}
```

- `inputs` is optional — only needed if the edge declares any (see the edge
  inspector's "Transition-time inputs"). Keys are the input's `name`; a
  required input missing here fails the request (see responses below).
- No authentication header, cookie, or CSRF token is needed or checked —
  the signature in the URL's query string is the only thing verified.
- The request is rate-limited (60 requests/minute per caller).

## 4. Responses

| Status | Body | Meaning |
| --- | --- | --- |
| `200` | `{"ok": true, "edge_id": "...", "to": "<node id the record landed on>"}` | Fired successfully. |
| `403` | (no body — Laravel's own signed-URL rejection) | Missing/invalid/expired signature. The URL was tampered with, mistyped, or (if it was generated with an expiration) has expired. |
| `404` | `{"ok": false, "error": "..."}` | The instance no longer exists, or the named edge isn't in its current graph. |
| `422` | `{"ok": false, "error": "..."}` | The edge exists but either isn't a `webhook`-triggered edge, isn't reachable from the record's current state right now, a precondition on the edge wasn't met, or a required input was missing. |

A `422` is not necessarily an error on your end — it can mean the record has
already moved on (e.g. someone else already actioned it, or a timer beat you
to it) by the time your callback arrived. Treat it as "nothing to do" rather
than retrying indefinitely.

## What firing a webhook edge does and doesn't do

- Runs as "system" — the same way a timer- or automatic-triggered edge does.
  There is no actor to check an `actor_rule` against, so none is checked.
- **Preconditions still run.** A webhook cannot force through a transition
  the graph itself would otherwise reject.
- Any `actions` on the edge (send an email, start a timer, call another
  webhook, ...) still fire, exactly as they would for any other trigger.
- The transition is recorded in the record's workflow timeline like any
  other, with no actor shown (this is what "System" in the timeline means).
